How to make an HDR JPEG with a PQ ICC profile

By Nimrod Yarkoni · Updated 17 November 2026

For Superwhite's HDR JPEG workflow, two things must agree: the pixel values must be encoded for PQ HDR, and the JPEG must carry the matching Rec.2100 PQ ICC profile. A normal JPEG with a new profile label is not a correct conversion.

Choose the HDR format for your use case

HDR JPEG is an umbrella term. A gain-map JPEG carries a base rendition plus extra information for HDR reconstruction. Superwhite uses a different route: a PQ-encoded JPEG with a matching embedded ICC profile. It does not currently export a gain-map JPEG or a separate SDR rendition.

Choose deliberately. If you need a paired SDR/HDR representation, investigate a gain-map workflow. If you want Superwhite's brighter-than-white treatment on a surface that preserves its original JPEG, the PQ route is the one described here.

The conversion pipeline

  1. Decode your source correctly. Interpret the source colour space and flatten transparency onto the intended background for JPEG output.
  2. Work in linear light. Convert source values before applying luminance and colour-space transforms.
  3. Choose the boost. Superwhite uses a threshold to boost white and near-white areas while retaining an SDR reference for other pixels.
  4. Encode PQ values. Use the ST 2084 transfer function with consistent luminance units and the colour space described by the output profile.
  5. Handle quantisation. An 8-bit JPEG can show banding or amplify near-white noise. Superwhite applies noise flattening and dithering, then encodes high-quality 4:4:4 JPEG.
  6. Embed the matching ICC profile. Preserve it through delivery and verify on the intended browser and display.

Embed a small ICC profile in JPEG: JavaScript example

// The JPEG pixels must already be encoded for the PQ profile.
// This adds one ICC APP2 segment; it does not convert sRGB to HDR.
function embedSmallICC(jpeg, icc) {
  if (jpeg[0] !== 0xff || jpeg[1] !== 0xd8) throw Error('Expected JPEG');
  if (icc.length > 65519) throw Error('Split large ICC profiles into segments');
  const tag = new TextEncoder().encode('ICC_PROFILE\0');
  const payload = new Uint8Array(icc.length + 14);
  payload.set(tag); payload[12] = 1; payload[13] = 1;
  payload.set(icc, 14);
  const length = payload.length + 2;
  const segment = Uint8Array.of(0xff, 0xe2, length >> 8, length & 255);
  let pos = 2;
  while (pos + 4 <= jpeg.length && jpeg[pos] === 0xff &&
         (jpeg[pos + 1] === 0xe0 || jpeg[pos + 1] === 0xe1)) {
    const size = (jpeg[pos + 2] << 8) | jpeg[pos + 3];
    if (size < 2 || pos + size + 2 > jpeg.length) throw Error('Invalid APP segment');
    pos += size + 2;
  }
  const out = new Uint8Array(jpeg.length + payload.length + 4);
  out.set(jpeg.subarray(0, pos)); out.set(segment, pos);
  out.set(payload, pos + 4);
  out.set(jpeg.subarray(pos), pos + 4 + payload.length);
  return out;
}

This example takes JPEG bytes and ICC bytes as Uint8Array inputs. It inserts an APP2 ICC segment after initial APP0/APP1 segments. Use an input with no existing ICC profile; a general-purpose implementation must replace or remove old ICC segments, support multi-segment profiles and validate the complete JPEG structure.

The code only embeds metadata. It does not perform colour conversion, generate a PQ profile, encode PQ pixels or make an arbitrary JPEG a valid HDR image. The profile and encoded pixels must match.

Check the output before shipping it

  • Inspect the embedded profile and confirm it is the one used to encode the pixel data.
  • Check highlights, gradients and coloured edges at multiple glow settings.
  • Test compatible HDR and SDR rendering paths. A CSS HDR media query is not a format-conformance test.
  • Fetch the actual deployed image. Compare it with the generated bytes to catch transformations in the CDN or CMS.
  • Avoid reprocessing an already PQ-encoded export as if it were ordinary sRGB. Keep the source image.

Frequently asked questions

Is adding a PQ ICC profile enough to make an SDR JPEG HDR?

No. The pixel values must also be converted for the transfer function, colour space and luminance convention represented by that profile.

Does this example generate a gain-map JPEG?

No. It demonstrates embedding a small ICC profile in an already encoded JPEG. Gain-map JPEG is a different workflow.

Why can an HDR JPEG look washed out or banded?

Possible causes include mismatched pixel encoding and profile, an unsupported renderer, quantisation, repeated PQ conversion or an image service changing the file. Test the original file and the delivered version separately.
